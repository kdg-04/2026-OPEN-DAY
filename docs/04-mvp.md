**AI DX센터 커너비 구출작전**
Team 23 · 강대경 · 이0혜 · 조0영

2026 연암공과대학교 AI DX 센터 OPEN DAY 아이디어톤 대상 수상작

> **이 문서에 대하여**
>
> 이 문서는 발표 당시의 산출물이 **아니다.**

> 현재 자료만으로 확정할 수 없는 항목은 지어내지 않고 `[확인 필요]`로 표시했다.

## 0. 한 줄 정의

> **30명 규모 견학 1회를, QR 접속부터 미션 클리어까지 이 시스템만으로 운영한다.**

아이디어톤에서 제시한 전체 구상 중 **실제로 현장에서 한 번 돌려볼 수 있는 최소 단위**를 잘라낸 것이 이 MVP다.

### 판단 기준

기능이 몇 개인지가 아니라 **이 질문 하나**로 범위를 정했다.

> *"AI CREW가 종이와 엑셀 없이, 이 시스템만 보고 견학 한 회차를 끝까지 운영할 수 있는가?"*

여기에 필요한 것만 넣고, 나머지는 전부 뺐다.

## 1. 범위

### 넣는 것 (In Scope)

| # | 기능 | 이유 |
|---|---|---|
| 1 | 세션 생성 · 조 자동 편성 · 타임테이블 자동 산출 | 이게 없으면 운영 자체가 시작되지 않는다 |
| 2 | QR / 세션 코드 접속 | 1회성 방문객에게 진입 장벽이 없어야 한다 |
| 3 | 학생 미션 화면 (역할 · 절차 · 타이머) | **역할 분리**가 이 프로젝트의 핵심 가설이다 |
| 4 | 라운드별 조작자 자동 교대 | 전원 참여를 보장하는 장치 |
| 5 | AI CREW 미션 완료 처리 | 꿀이 지급되는 유일한 입구 |
| 6 | 꿀 집계 · 조별 랭킹 | 동기 부여의 즉각적 피드백 |
| 7 | 메인 스테이지 실시간 게이지 | 현장 몰입의 핵심 장치 |
| 8 | 미션 클리어 화면 + 만족도 1문항 | 마무리와 데이터 수집 |
| 9 | 세션 종료 후 CSV 리포트 | 대시보드 대신 최소한의 데이터 회수 |

### 빼는 것 (Out of Scope)

| 뺀 것 | 왜 뺐나 | 대체 |
|---|---|---|
| 운영 인사이트 대시보드 | 데이터가 쌓이기 전에는 분석할 것이 없다. 최소 5~10회차 운영 후에 의미가 생긴다 | CSV 리포트 |
| 개인 참여도 차등 배분 | 기획 단계에서 의도한 장치지만 산식이 확정되지 않았고, 잘못 설계하면 조 내 갈등을 만든다 | 조작 횟수 기록만 남긴다 |
| 회원가입 · 로그인 | 1회성 방문객에게 가입은 치명적인 이탈 지점이다 | 세션 코드 + 조 토큰 |
| 다국어 | 첫 검증 대상은 국내 고교 단체 견학이다 | — |
| AI 기반 동선 추천 | 추천할 근거 데이터가 아직 없다 | — |
| 역대 반 기록 랭킹 | 회차가 1회면 비교 대상이 없다 | 2회차부터 자동 활성 |

> **원칙:** 뺀 기능은 "나중에 하자"가 아니라 **"지금은 검증할 수 없다"**는 이유로 뺐다.

## 6. 핵심 로직

### 6-1. 조 편성과 완전 로테이션

부스 수를 `B`, 견학 인원을 `N`, 체류 시간을 `T`라 할 때:

```
G = B - 1                  # 조 수 — 부스보다 하나 적게 (1개는 항상 휴식 버퍼)
R = G                      # 라운드 수 — 각 조가 모든 부스를 1회씩
M = ceil(N / G)            # 조당 인원
L = floor(T / R)           # 라운드 길이 (미션 + 이동·세팅)
```

배치는 **순환 라틴방격** 한 줄로 결정된다. (`g`: 조 인덱스 0..G-1, `r`: 라운드 인덱스 0..R-1)

```
booth(g, r) = (g - r) mod B      # 조 g가 라운드 r에 갈 부스
rest(r)     = (G - r) mod B      # 그 라운드에 비는 부스
```

**이 한 줄이 보장하는 것**

- 같은 라운드에 두 조가 같은 부스에 배정되지 않는다 → **대기열이 발생할 수 없다**
- 각 조는 각 부스를 정확히 1회 경험한다 → **체험 쏠림이 구조적으로 제거된다**
- `booth(g, r) = 0`인 경우는 `g = r`일 때뿐 → **병목 부스를 전 조가 정확히 1회씩** 대각선으로 배정받는다
- 매 라운드 정확히 1개 부스가 비고, 그 부스가 순환하며 **지연 흡수 버퍼**가 된다

> 검증: `B=7, N=30, T=30분` → `G=6, R=6, M=5, L=4분`
> (미션 3분 20초 + 이동·세팅 40초) — 목업의 산출값과 일치한다.

### 6-2. 역할 배정과 조작자 교대

```
operator(team, r) = team.members[r mod M]
```

`R = 6`, `M = 5`이면 조작자 인덱스는 `0,1,2,3,4,0` → **전원 최소 1회 직접 조작**이 산술적으로 보장된다.

미션 화면의 표시 규칙:

| 역할 | 보이는 것 | 보이지 않는 것 |
|---|---|---|
| 조작자 | 부스명, 남은 시간, "지시를 기다리세요" | **미션 절차** |
| 지시자 | 부스명, 남은 시간, **미션 절차 전체** | 조작자의 실제 화면 |

같은 화면 컴포넌트에서 `participant.id === assignment.operator_id` 여부로 절차 블록만 가린다.
**서버가 조작자에게는 절차를 내려보내지 않는다** — 클라이언트에서 숨기면 우회가 가능하므로, 응답 자체를 분기한다.

### 6-3. 꿀 산정 (MVP 안)

```
미션 완료           +60
제한 시간 내 완료    +15
신규 조작자 등판     +10      # 아직 조작하지 않은 조원이 맡은 경우
부스 난이도 가중     × 0.8 ~ 1.2
────────────────────────────
만족도 응답 (조 1회) +150     # 세션 종료 시 1회, 게이팅 아님
```

라운드당 조별 60~100 꿀 → 6조 × 6라운드 ≈ **3,000~3,300**.
목표 꿀 3,000과 맞물려 **"열심히 하면 넘고, 대충 해도 아깝게 근접"**하는 구간에 놓인다.

> ⚠️ **[확인 필요]** 위 수치는 목업의 결과값(참여 꿀 3,090 + 설문 꿀 150 = 3,240)을 역산해 구성한 것이다.
> 실제 운영 전 리허설로 보정이 필요하다.

**설계 원칙:** 게이지는 달성/미달이 아니라 **총량**을 표시한다. 목표에 못 미쳐도 **커너비는 구해낸다.**
미달로 끝나는 견학은 만들지 않는다.

## 7. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | Next.js (App Router) | 학생 · 크루 · 운영자 · 스테이지 4개 뷰를 한 코드베이스로 |
| 백엔드 / DB | Supabase (Postgres + Realtime) | 게이지와 랭킹에 실시간 구독이 필수. 별도 서버 불필요 |
| 배포 | Vercel | 현장 당일 즉시 배포/롤백 |
| 인증 | **없음** — 세션 코드 + 조 토큰 | 1회성 방문객에게 가입은 최대 이탈 지점 |
| QR | 세션 URL 인코딩 | 인쇄해서 중앙 광장에 비치 |

핵심 판단은 **인증을 넣지 않는 것**이다.
견학 현장에서 30명이 동시에 회원가입하는 순간, 브리핑 단계가 그대로 무너진다.

## 8. 개발 순서 (4주)

| 주차 | 목표 | 완료 기준 |
|---|---|---|
| **W1** | 데이터 모델 + 운영자 세션 생성 · 조 편성 | 30/30/7 입력 시 목업과 동일한 배치표가 나온다 |
| **W2** | 학생 앱 (접속 → 브리핑 → 미션 → 역할 분리) | 조작자에게 절차가 내려가지 않는다 |
| **W3** | 크루 콘솔 + 꿀 집계 + 랭킹 + 클리어 | 한 라운드가 완결된다 |
| **W4** | 스테이지 실시간 게이지 + 리허설 | **실제 30명으로 1회 완주** |

W4의 리허설이 이 MVP의 진짜 산출물이다. 코드가 아니라 **"한 번 돌아갔다"는 사실**이 검증 결과다.

## 9. 성공 지표

| 지표 | 목표 | 측정 |
|---|---|---|
| **직접 조작 참여율** | ≥ 90% | 조작자로 1회 이상 등판한 인원 ÷ 전체 |
| 미션 완료율 | ≥ 85% | 완료 Assignment ÷ 전체 Assignment |
| 타임테이블 준수 | 라운드 지연 ≤ 1회 | 라운드 실제 종료 − 예정 종료 |
| 만족도 응답률 | ≥ 70% | Survey ÷ 참가자 |
| 운영자 개입 | 0회 | 수기 조정이 필요했던 횟수 |

**직접 조작 참여율이 유일한 핵심 지표**다.
나머지가 모두 좋아도 이 숫자가 낮으면 이 프로젝트는 실패한 것이다. 기존 방식의 추정치는 33% 수준이다.

## 10. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 센터 와이파이 불안정 | 완료 처리 실패, 게이지 정지 | 크루 콘솔에 오프라인 큐 — 복구 시 자동 동기화 |
| 학생 휴대폰 미소지 / 배터리 | 미션 화면 접근 불가 | **조당 1대로 작동**하도록 설계. 크루 태블릿 대여 |

| 특정 부스 지속 지연 | 전체 타임테이블 붕괴 | 버퍼 부스가 흡수. 운영자가 라운드 길이 즉시 조정 |
| 조작자 교대 미이행 | 핵심 가설 무효화 | 미교대 조원을 앱 화면에 상시 노출 + 크루 구두 안내 |
| 인원이 조 수로 안 나눠떨어짐 | 조별 인원 불균형 | `M = ceil(N/G)`로 앞 조부터 채움. 편차 1명 이내 |

```
역대 반 기록 · 다국어
   ↓
동선 자동 추천 · 혼잡도 예측
```

순서의 근거는 **데이터**다. 대시보드는 데이터가 쌓인 뒤에, 참여도 산식은 실제 조작 패턴을 본 뒤에 만든다.
